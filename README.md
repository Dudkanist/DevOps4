# REST API для управления списком задач (todo-api)

Простой Python-сервис на базе Flask, предоставляющий REST API для управления списком задач. В проекте полностью настроен, оптимизирован и успешно протестирован автоматизированный CI/CD пайплайн повышенной сложности (**Вариант 2**).

---

## Основные возможности CI/CD пайплайна

* **Качество кода (Lint):** Автоматическая проверка стиля кода с помощью `flake8` (максимальная длина строки расширена по ТЗ до 120 символов).
* **Матричное тестирование (Test):** Параллельный запуск тестов (`pytest` + `pytest-cov`) на трех версиях среды: Python 3.10, 3.11 и 3.12 для проверки обратной совместимости.
* **Сборка (Build):** Автоматическое создание изолированного Docker-образа при пуше в целевые ветки и сохранение его структуры в артефакт `dist/image.tar`.
* **Безопасность (SBOM):** Анализ состава готового образа утилитой `Syft` (v1.4.1) и генерация отчетов о зависимостях (Software Bill of Materials) в стандартах CycloneDX и SPDX JSON с удержанием артефактов 90 дней.
* **Поставка (Deploy):** Раздельные окружения для Staging (автоматически для ветки `develop`) и Production (ручной запуск по релизному тегу).

## Важное примечание: Вынужденный перенос пайплайна на GitHub Actions

В соответствии с описанием лабораторной работы («*Разработка CI/CD Pipeline в GitLab(Github)*»), в качестве альтернативной и более стабильной платформы автоматизации был выбран **GitHub Actions** (конфигурация развернута в `.github/workflows/main.yml`).

Отказ от использования публичного облака `gitlab.com` и перенос логики пайплайна были вызваны инфраструктурными ограничениями со стороны платформы GitLab при регистрации аккаунта. 7Платформа не позволяет зарегистрироваться испльзуя мобильный телефонный номер начинающийся на +7, а как альтернатриву просит предоставления банковской карты, чего делать не хочется. Без этого шага создание аккаунта невозможно.
**Итог переноса:** Вся строгая логика, требования к переиспользованию блоков, правила запуска (`workflow.rules`), параллельные матрицы сред (Python 3.10–3.12) и supply chain security (генерация SBOM через `Syft` с утилизацией `docker load` из тар-архива) были полностью сохранены и успешно имплементированы на синтаксисе GitHub Actions. Пайплайн стабилен и завершается со статусом `Success`.
